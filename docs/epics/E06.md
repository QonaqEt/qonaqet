## Goal
"İsmarla" sütunu: biznes günlük təklifləri, askıda məhsullar, claim-lər, atomik kvota və ləyaqəti qoruyan təhvil.

## Scope
Təkliflər (daily/suspended), atomik kvota ilə claim, limitlər, QR/qısa kod, təhvil, müddət bitmə job-u, məxfilik testləri.

## Out of scope
Pullu `Remote` təklifləri və hovuz claim-ləri (E08), ödəniş və ledger (E07).

## Acceptance criteria
- [ ] Eyni anda 100 paralel claim cəhdində kvota heç vaxt aşılmır
- [ ] Biznes endpoint-ləri alıcının kimliyini heç vaxt qaytarmır (test sübut edir)
- [ ] Həssas kateqoriyada staff "Qonaq" etiketini görür, kateqoriya adını yox
- [ ] 30 dəqiqədən sonra istifadə olunmayan rezerv avtomatik buraxılır

## Tasks

### E06-T01 · Offer aqreqatı: BusinessDaily və Suspended
- area: backend
- priority: p0
- size: L

Acceptance:
- [ ] `BusinessDaily`: `dailyQuota`, `usedToday`, `quotaDate`, `availableFrom`/`availableTo`, `isActive`
- [ ] `Suspended`: `totalQuantity`, `remaining`, `donorUserId?`, `createdByStaffId`
- [ ] `donorDisplay` (`Anonymous` | `Named`) və `donorName?`
- [ ] Partial indekslər: (`businessId`, `type`), (`categoryId`, `type`)

### E06-T02 · Atomik claim və gündəlik kvotanın sıfırlanması
- area: backend
- priority: p0
- size: L

Acceptance:
- [ ] Azalma tək şərtli `FindOneAndUpdate` ilə olur (`remaining > 0` / `usedToday < dailyQuota`)
- [ ] Gündəlik kvota Bakı tarixinə görə lazy sıfırlanır
- [ ] Paralel yük testi kvotanın aşılmadığını sübut edir
- [ ] Kvota bitəndə `quota_exhausted` qaytarılır

### E06-T03 · Limitlər və ləyaqətlilik qaydaları
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] İstifadəçidə eyni anda maksimum 1 aktiv `Reserved` claim olur
- [ ] Bir təklifdən gündə 1 claim
- [ ] İstifadəçinin kateqoriyaları arasında ən səxavətli limit tətbiq olunur
- [ ] Limitlər yalnız sosial qonaqlığa aiddir; şəxsə ünvanlanmış hədiyyələrə yox
- [ ] Donor alıcını nə seçir, nə görür

### E06-T04 · QR token və qısa kod
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Claim QR-ı: `base64url("c." + claimId + "." + HMAC)` və birdəfəlikdir
- [ ] Qısa kod insan üçün oxunaqlıdır və təsadüfi təxmin edilə bilmir
- [ ] Token-lər heç vaxt loglanmır
- [ ] Endpoint rate-limitlidir

### E06-T05 · Claim təhvili (staff tərəfi)
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Təhvil idempotentdir; təkrar cəhd `already_redeemed` qaytarır
- [ ] Staff yalnız məhsulu, statusu və məbləği görür
- [ ] Təhvil `ClaimRedeemed` outbox hadisəsi yaradır
- [ ] `BusinessDaily` / `Suspended` üçün komissiya yoxdur

### E06-T06 · Müddət bitmə job-u və rezervin buraxılması
- area: backend
- priority: p0
- size: S

Acceptance:
- [ ] Rezerv TTL-i 30 dəqiqədir
- [ ] Job köhnəlmiş claim-ləri `Expired` edir və vahidi/rezervi geri qaytarır
- [ ] Job atomik status keçidi ilə işi götürür (ikiqat emal yoxdur)

### E06-T07 · Məxfilik testləri
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Biznes cavablarında alıcının adı, email-i və ya id-si yoxdur
- [ ] `privacyLevel = Sensitive` kateqoriyada etiket "Qonaq"dır
- [ ] Donor yalnız aqreqat görür, konkret alıcını yox
- [ ] Bu yoxlamalar ayrıca test sinfindədir və CI-da məcburidir
