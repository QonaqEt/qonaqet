## Goal
Platformanın əsas sütunu: şəxsə ünvanlanmış hədiyyələr — məhsul, vauçer və şəbəkə vauçeri, link ilə paylaşım,
qismən təhvil, planlanmış çatdırılma və müddət bitməsində geri qaytarma/bağışlama.

## Scope
Gift aqreqatı, items/voucher/network, link token-ləri + public API, hesaba əlavə etmə, çatdırılma/müddət job-ları,
qismən təhvil, ləğv/linkin yenidən verilməsi, müddət bitməsində refund və ya hovuza bağışlama.

## Out of scope
Korporativ sifarişlər (E10), partnyor tərəfindən ifraz olunan hədiyyələr (E13), UI (E15, E19).

## Acceptance criteria
- [ ] Hədiyyə email və ya link ilə çatır; hər ikisi eyni hədiyyəni açır
- [ ] Vauçer qismən təhvil olunur və qalıq düzgün azalır
- [ ] Paralel təhvil cəhdində qalıq mənfiyə düşmür; ikinci cəhd `gift_changed` alır
- [ ] Staff nə göndərənin, nə alıcının şəxsi məlumatını görmür (test sübut edir)
- [ ] Müddəti bitən hədiyyə `expiryAction`-a uyğun refund olunur və ya hovuza bağışlanır

## Tasks

### E09-T01 · Gift aqreqatı və qiymətin serverdə hesablanması
- area: backend
- priority: p0
- size: L

Acceptance:
- [ ] `kind` (`Items` | `Voucher`), `scope` (`Business` | `Network`); `Network` yalnız `Voucher` ilə
- [ ] `Items`: bir biznesin 1–10 `isGiftable` məhsulu
- [ ] Biznes vauçeri: biznesin `voucherMinQepik`–`voucherMaxQepik` aralığında
- [ ] Şəbəkə vauçeri: 2–200 AZN
- [ ] `fulfillmentType = Pickup` sahəsi mövcuddur (gələcək `Delivery` üçün)
- [ ] Qiymət yalnız serverdə hesablanır; klientin göndərdiyi məbləğ qəbul edilmir

### E09-T02 · Hədiyyənin yaradılması və ödəniş
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] `POST gifts` → `{giftId, paymentUrl}`; hədiyyə `AwaitingPayment` statusunda yaranır
- [ ] Alıcı ya email, ya "linki özüm göndərəcəm"dir; alıcı adı məcburidir
- [ ] Tema, mesaj (≤500 simvol), `senderDisplay`, `deliverAt` (≤90 gün) saxlanılır
- [ ] Ödəniş təsdiqində status `Scheduled` olur, link token yaradılır və göndərənə bir dəfə qaytarılır
- [ ] `Idempotency-Key` məcburidir

### E09-T03 · Link token-ləri və public hədiyyə API-si
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Token 32 təsadüfi bayt, base64url; yalnız `linkTokenHash` saxlanılır
- [ ] `GET public/gifts/{token}` login tələb etmir və rate-limitlidir
- [ ] Token heç vaxt loglanmır (test sübut edir)
- [ ] İlk açılış statusu `Opened` edir və göndərənə bildiriş gedir
- [ ] `gifts.linkTokenHash` partial unikaldır

### E09-T04 · Hesaba əlavə etmə və linkin yenidən verilməsi
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] `POST public/gifts/{token}/claim` (auth) `recipientUserId` təyin edir
- [ ] Əlavə etdikdən sonra link hələ də işləyir (app-ı olmayan valideyn üçün)
- [ ] `POST gifts/{id}/reissue-link` yeni token yaradır və köhnə hash-i əvəz edir
- [ ] Yalnız göndərən linki yenidən verə bilir

### E09-T05 · Çatdırılma job-u
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Hər dəqiqə `Scheduled` və `deliverAt ≤ now` hədiyyələri götürür
- [ ] Email varsa temalı email göndərir: link, göndərən (və ya "Anonim dost"), mesaj, məzmun
- [ ] Email bir istifadəçiyə aiddirsə push da gedir və `recipientUserId` təyin olunur
- [ ] Göndərənə "Hədiyyəniz çatdırıldı" bildirişi gedir
- [ ] Job idempotentdir: təkrar işə düşəndə ikinci email getmir

### E09-T06 · Təhvil: QR, preview və qismən təhvil
- area: backend
- priority: p0
- size: L

Acceptance:
- [ ] QR payload: `base64url("g." + giftId + "." + HMACSHA256(giftId, secret))`, tam təhvilə qədər təkrar işlənir
- [ ] `POST business/redeem/preview` yalnız məzmun və qalığı qaytarır
- [ ] `Items`: sətir üzrə miqdar ≤ qalıq; `Voucher`: istənilən məbləğ ≤ qalıq
- [ ] Şəbəkə vauçeri `acceptsNetworkVouchers` olan istənilən biznesdə işləyir
- [ ] Tək Mongo tranzaksiyası: `giftRedemptions` + qalıq/status + `GiftRedeemed` outbox
- [ ] Optimistik `version` ilə şərti yeniləmə; bir dəfə retry, sonra `gift_changed`

### E09-T09 · Müddət bitməsi, xatırlatma və expiryAction
- area: backend
- priority: p0
- size: L

Acceptance:

- [ ] 7 gün qalmış alıcıya xatırlatma gedir (bir dəfə)
- [ ] `RefundToPayer`: qalıq dəyər qismən refund olunur

- [ ] Status `Expired` (+ refund olunubsa `Refunded`) olur
- [ ] Job idempotentdir və 15 dəqiqədən bir işləyir
