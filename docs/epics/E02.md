## Goal
Email OTP ilə giriş, JWT + refresh rotasiyası, rollar və siyasətlər, profil idarəetməsi — bütün digər
epic-lərin istifadəçi kontekstinə etibar edə biləcəyi səviyyədə.

## Scope
Email OTP, JWT + refresh rotation, rollar/policy-lər, profil, FCM token-ləri, hesabın soft delete-i, blok.

## Out of scope
Partnyor client-credentials autentifikasiyası (E13), kateqoriya təsdiqi (E05).

## Acceptance criteria
- [ ] İstifadəçi email → 6 rəqəmli kod → ad axını ilə qeydiyyatdan keçir və giriş edir
- [ ] Refresh token rotasiya olunur; oğurlanmış köhnə token təkrar işlənə bilmir
- [ ] Bloklanmış istifadəçi giriş edə bilmir və aktiv claim-ləri ləğv olunur
- [ ] Silinmiş hesabın email-i yenidən qeydiyyat üçün sərbəstdir (partial unique index)

## Tasks

### E02-T01 · Email OTP göndərmə və yoxlama
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] 6 rəqəm, 10 dəqiqə etibarlı, maksimum 5 cəhd, 15 dəqiqədə maksimum 3 göndərmə
- [ ] Yalnız `codeHash` saxlanılır, açıq kod yox
- [ ] OTP yalnız Development-də loglanır
- [ ] Endpoint rate-limitlidir; mövcud/olmayan email fərqi cavabdan sezilmir

### E02-T02 · JWT ifraz və refresh rotasiyası
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Access token qısa ömürlü, refresh token hash-lənmiş saxlanılır
- [ ] Hər refresh-də köhnə token ləğv olunur və yenisi verilir
- [ ] Ləğv olunmuş token-in təkrar işlədilməsi aşkarlanır və istifadəçinin bütün sessiyaları bağlanır
- [ ] `POST auth/logout` refresh token-i ləğv edir

### E02-T03 · Rollar və avtorizasiya siyasətləri
- area: backend
- priority: p0
- size: M

Acceptance:
- [ ] Rollar: `User`, `BusinessStaff`, `BusinessOwner`, `CorporateUser`, `BrandUser`, `Admin`
- [ ] Siyasətlər pipeline-da tətbiq olunur, controller-də deyil
- [ ] Resurs yoxlaması handler-dədir (məs. "staff bu biznesə aiddir")
- [ ] İcazəsiz giriş 403 + sabit kod qaytarır

### E02-T04 · Profil: GET/PATCH/DELETE me
- area: backend
- priority: p0
- size: S

Acceptance:
- [ ] Ad, soyad, avatar faylı yenilənir
- [ ] `DELETE me` soft delete edir və girişi bloklayır
- [ ] Silinmə audit log-a düşür

### E02-T05 · FCM token-lərinin idarəsi
- area: backend
- priority: p1
- size: XS

Acceptance:
- [ ] `POST me/fcm-token` token əlavə edir, dublikat yaratmır
- [ ] Etibarsız token-lər göndərmə zamanı təmizlənir

### E02-T06 · İstifadəçi bloklama
- area: backend
- priority: p1
- size: S

Acceptance:
- [ ] Admin istifadəçini bloklayır/açır
- [ ] Bloklanmış istifadəçi claim yarada və hədiyyə göndərə bilmir
- [ ] Bloklama zamanı aktiv claim-lər ləğv olunur və ehtiyat buraxılır
- [ ] Bloklanmış istifadəçi reytinq lövhələrində görünmür

### E02-T07 · Partial unique index-lər və email təkrar istifadəsi
- area: backend
- priority: p1
- size: XS

Acceptance:
- [ ] `users.email` `{ isDeleted: false }` üzərində unikaldır
- [ ] Hesab silindikdən sonra eyni email ilə yeni hesab açıla bilir
- [ ] Testlər bunu sübut edir
